# Repo audit, 2026-11-10

Asked for by the owner: read the project, find what is broken, inconsistent, inefficient or no longer needed; fix what
is certain, list the rest. Done on branch `repo-audit` from main `a39a5f114` (so without PR #22).

## How it was checked

- Every relative link and anchor in the 155 tracked markdown files (a script; `.scratch/` and changelogs left out).
- Every file in `scripts/`: is it referenced by a package script, a workflow, a hook, another script or a doc.
- `git grep` for what xin-pi removed or does not have (Nix, the upstream installers, removed packages and workflows,
  self-update).
- Package metadata, docs navigation (`docs.json`), root and package npm scripts, CI, issue templates, `SECURITY.md`,
  `CONTRIBUTING.md`, `AGENTS.md`, `.pi/` prompts, skills and extensions.
- Settings keys, environment variables and commands in the code against the docs.
- The exports of the xin-pi extensions (`subagent`, `upstream`, codemode `addons` and `scripts`) against their uses.
- `runner.ts` read in full; the files written in the last week reread for behaviour, with small experiments.
- Cost of agent and workflow discovery, which runs on every `Agent` call: 0.27 ms and 0.05 ms. Not a problem.

Not read line by line: the code inherited from pi (about 1500 files), and the subagent files that had three rounds of
review before this week (`worktree.ts`, `subagent-screen.ts`, `process-tree.ts`, `upstream/`).

## Fixed

Broken:

- A saved workflow was skipped as "cannot import modules" whenever the word `import` appeared in a prompt, in code a
  prompt quotes, or in a comment (`workflows.ts`). The check now looks at code only.
- Ten anchor links in the inherited docs pointed at sections that do not exist.
- `quickstart.md` installed upstream pi (the `pi.dev` installer, a Nix flake) and verified with `pi --version`.

Inconsistent:

- "xpi is installed from source" (the `xpi update` message and help, `cli.md`, `settings.md`,
  `environment-variables.md`, `docs/xin-pi.md`): it is also on npm and has release binaries. The message now says to
  reinstall it the way it was installed.
- `SECURITY.md` sent reports to the upstream company's mailbox and put upstream's `pi.dev` in scope.
- Root `README.md`: the package table listed 5 of 9 packages; "the Pi CLI"; `xpi update --self` (xpi has no
  self-update); "npm publishes the validated tarballs" (npm is published by hand).
- `repository.url` of seven packages pointed at upstream, where their directories do not exist.
- `settings.md` did not name `builtin:subagent` and `builtin:upstream`, and had no word on the `subagent` block.
- `AGENTS.md` allowed only `feat`, `fix`, `docs` commits while `scripts/release.mjs` commits `chore:`.
- Two subagent tests used `await import()`, which `AGENTS.md` forbids.
- `fork.ts` built the child's directory by string concatenation where the rest uses `join`.

## For the owner to decide

1. **Seven library packages can be published, and `npm run publish` at the root would publish all of them.** The docs
   say only the CLI is published. The READMEs of `xpi-ai`, `xpi-agent-core`, `xpi-schema` and `xpi-telemetry` tell the
   reader to `npm install` packages that are not on npm (404), and `docs/sdk.md` describes an SDK that
   `docs/xin-pi.md` says does not work from an npm install. Decide: publish the libraries, or mark them private, remove
   `publish`, `publish:dry` and `version:*` from the root scripts, and say in those READMEs how to use them from the
   repo.
2. **Changelogs.** `AGENTS.md` has a Changelog section (entries under `[Unreleased]`, upstream issue links),
   `CONTRIBUTING.md` says not to edit `CHANGELOG.md`, `docs/xin-pi.md` says "add a changelog line if the package keeps
   one", and no xin-pi change has added one. Eight inherited `CHANGELOG.md` files are in the repo and `/changelog`
   shows upstream's. Release notes come from GitHub. Decide: keep and write them, or drop the section and the files.
3. **`pkg:*` labels** are required for issues by `AGENTS.md`; the repo has no such labels.
4. **Ten scripts nothing refers to** (about 2,500 lines, upstream maintainer tooling): `auto-pi.sh`,
   `edit-tool-stats.mjs`, `read-tool-stats.mjs`, `tool-stats.ts`, `stats.ts`, `cost.ts`, `session-context-stats.mjs`,
   `session-transcripts.ts`, `repro-5893-wsl-bash.mjs`, `update-source-imports-to-ts.sh`.
5. **Upstream maintainer prompts and an extension in `.pi/`**, loaded by every xpi started in this repo:
   `prompts/cl.md` (changelog audit, with a dead link), `wr.md` (finish with a changelog entry), `sa.md` (security
   advisory), `pr.md`, `is.md`, `dup.md`; `extensions/import-repro.ts` (imports sessions shared by upstream's issue CI,
   which was removed).
6. **The inherited docs say `pi`** in commands and prose (about 40 files). `cli.md` documents `pi update` as a
   self-update with a table of forms xpi does not have. A rename can be done by script; it also moves these docs
   further from upstream's, which makes later ports of doc changes harder.
7. **Hardcoded keys.** `AGENTS.md`: "Never hardcode key checks". The subagent panel and screen hardcode theirs (`x`,
   `r`, `s`, `p`, `enter`, arrows; 21 `matchesKey` calls). They cannot be rebound.
8. **The `subagent` settings block is not in the settings schema**, so editors neither complete nor check it.
9. **Eval results are committed on every recorded run** (`test/subagent/evals/results/`, 12 files, 127 KB so far).
10. **Names left from pi**: `pi-test.sh`, `pi-test.bat`, `pi-test.ps1`; the root README's containerization and
    development sections say "Pi".
11. **`docs/subagent.md` has grown to about 700 lines**, a section per feature in the order they were built. It would
    read better reorganized by task.
12. **About 55 exports in the subagent extension are used only in their own file.** Harmless; removing them is churn.

## For PR #22 (not on this branch)

- `runs.ts` rewrites the whole run file on every `Agent` call, twice per call (start and end), and the file holds every
  result. For a run of 1,000 agents that is 2,000 writes of a file that grows to megabytes. Write once per call, or
  append.
